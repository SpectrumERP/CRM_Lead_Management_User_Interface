CRM Dashboard - Backend API: Summary and Missing Points
Date: 05 Oct 2026
Reference: Dashboard_Backend_API_Requirements_Final.docx
Checked against the frontend code only, not the live API.

==================================================
A. NEW APIs
==================================================
1. POST /api/crm/activities/search-data   (required)
   Returns all activities in one call. Replaces the one load-data call per lead/opportunity.

2. GET /api/crm/dashboard                  (optional, later)
   Needed only if the page is still slow.

==================================================
B. FIELDS TO ADD TO EXISTING APIs
==================================================
APIs: leads/search-data, opportunities/search-data, and the load-data API of each.

Lead + Opportunity:
  - stageChangedDate
  - lastActivityDate      (already exists; always send the key, null if there is none)
  - totalActivityCount, pendingActivityCount, overdueActivityCount
  - nextActivityNo, nextActivitySubject, nextActivityDate

Opportunity only:
  - wonDate, lostDate

Database:
  - New columns: StageChangedDate, WonDate, LostDate
  - One-time backfill for existing records
  - Save logic: set these dates only when the stage or status changes

==================================================
C. MISSING FROM THE REQUIREMENTS DOC (please add)
==================================================
1. Activities of a converted lead
   On conversion, the server copies the lead's activities to the opportunity,
   but the lead's copies stay Pending. The backend should close them when the
   lead is converted, or at least leave them out of the activity counts.

2. More filters for activities/search-data
   Add to the request:
     - recordType: "Lead" | "Opportunity" | null
     - leadNo / opportunityNo
   The same API can then return the activities of a single record.

3. Dashboard API (Change 3) response is incomplete
   - closingThisMonth is only a count. The list is also needed: opportunity,
     weighted value, last activity and pending activities.
   - Lead and opportunity pipelines are missing (count and value per stage).

4. Stagnant threshold
   stagnantDays=15 is only a query param of Change 3. search-data does not
   return daysInStage, so the frontend calculates it from stageChangedDate.
   Please state this in the doc.

5. lastActivityDate / overdue definition
   - The doc says MAX(ClosureDate or ScheduleDate). The frontend instead takes
     the completed activity with the latest scheduleDate + scheduleTime and
     uses its closureDate, else its scheduleDate. Please confirm which rule to use.
   - Is a Pending activity due today whose time has already passed overdue?
     The frontend currently compares the date only, not the time.
